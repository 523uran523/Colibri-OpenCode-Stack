# Стиль и язык

## Основные принципы
- Сразу объясняйте аббревиатуры, которые в документе встречаются впервые.
- Используйте термины и их язык последовательно.
- Новые термины объясняйте сразу или приводите ссылку на статью с объяснением.
- Названия переменных, классов и других важных терминов выделяйте полужирным. При этом мы не используем курсив для выделения, кроме каких-то исключительных случаев, когда нужно выделить пример в тексте.

## Активный залог
Используйте прямую речь. Избегайте длинных, сложноподчиненных предложений с пассивным залогом.

> Хорошо: Чтобы открыть список, нажмите кнопку Открыть.

> Плохо: Для открытия списка необходимо нажать кнопку Открыть.

## Обращение к читателю
Обращайтесь напрямую к читателю документа.

> Хорошо: Нажмите Ок, чтобы сохранить документ.

> Плохо: Пользователь должен нажать Ок, чтобы сохранить документ.

## Простые грамматические конструкции
Используйте самый ёмкий и простой глагол из возможных.

> Хорошо: Нажмите на стрелку для перехода между слайдами.

> Плохо: Можно использовать кнопку с изображением стрелки для перехода между слайдами.

## Язык написания документов
Основным языком является русский. Это касается и названия статей. Английский язык используется в следующих случаях:

- название иностранных брендов и продуктов (например, Facebook, Google, iOS);
- общепринятые сокращения (например, API, LLM, RS-триггер и проч.грнипе);
- общепринятые названия фреймворков, языков программирования и других подобных терминов (C++, JavaScript, GraphQL, NodeJS);
- имена функций, переменных, классов, структур, файлов.

## Структура документа
### Абзацы
Разбивайте параграфы на абзацы. В одном абзаце не должно быть больше шести предложений. Один абзац — одна законченная мысль. Главную идею лучше изложить в начале абзаца.

### Предложения
Пишите короткими предложениями. Если в предложении больше 12 слов, подумайте, как его уменьшить.

### Оформление документа
#### Скриншоты
Используйте скриншоты в следующих ситуациях:
- везде, где может возникнуть малейший вопрос по процессу работы;
- для демонстрации интерфейса, с которым предстоит работать пользователю;
- чтобы показать результат выполнения какой-либо операции.
Лучше один раз показать, чем подробно описывать.

Не используйте скриншоты в следующих случаях:
- для демонстрации кода;
- вместо перечисления полей, которые необходимо заполнить пользователю;
- для вставки таблиц с важными для работы параметрами.
Добавляйте пояснение к скриншоту. Поясняющий текст располагается непосредственно перед или сразу после скриншота. Следите, чтобы принадлежность описания к скриншоту легко считывалась. Если на скриншоте необходимо отметить несколько элементов, используйте указатели с нумерацией.

#### Таблицы и иллюстрации
Используйте вспомогательные инструменты для упорядочивания текста:
- длинные списки со ссылками и пояснениями стоит объединять в таблицы;
- порядок действий со многими переменными оформите в алгоритм или блок-схему для большей наглядности;
- для демонстрации последовательности действий полезно создавать gif-анимации.
#### Списки
Используйте списки, если речь идет о чем-то в количестве более двух. Так воспринимать перечень гораздо удобнее.
- маркированные списки применяйте для связанных между собой, но неупорядоченных данных;
- нумерованные списки используйте при перечислении данных, для которых важна последовательность.
Маркированные списки начинаются с маленькой буквы и в конце ставится точка с запятой. Если в маркированных списках каждый пункт это отдельное предложение, то допускается начинать его с большой буквы, а в конце ставить точку.

В начале каждого пункта нумерованного списка ставится цифра, каждый пункт начинается с большой буквы и в конце ставится точка.

#### Код в тексте
Для размещения многострочных блоков кода в тексте используйте блоки исходного кода.

Сокращайте куски кода, отмечая вырезанные части троеточием, чтобы читатель видел только нужный пример, без незначимых деталей.

#### Цифры
Однозначные числа пишите словами, все остальные – цифрами. Исключение, когда речь идет о значениях в интерфейсе или диапазонах — в этом случае пишите цифрами.

> Хорошо: Выберите первый вариант. Как смёржить два изменения. Допустимые значения — от 0 до 5.
> Плохо: Выберите 7 пункт.

#### Единицы измерения
Для параметров:
- Названия (ни полного, ни сокращённого) единиц измерения в описании параметра быть не должно (ни в заголовке, ни в тексте под спойлером);
- Если есть значение по умолчанию, то при нём единицы измерения пишутся;
- Единицы измерения пишутся по-русски;
- Если по умолчанию 0, то единицы НЕ пишутся; исключение - температура, там надо указать, это 0 К или 0 ℃
Для направленных портов:
- Единицы измерения обязательно указываются.

#### Десятичный разделитель
Везде используется точка (.)
