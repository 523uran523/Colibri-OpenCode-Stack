# Engee Agent 1.2.0 — переносимая версия

## Быстрый запуск на Windows

Полная инструкция находится в приложении: значок **?** в правом верхнем углу. Для чтения без сервера откройте `resources/web/public/help/guide.html`. Актуальная справка собрана в этой единой HTML-инструкции.

1. Распакуйте **весь** ZIP в обычную папку, в которой у вас есть право записи. Можно перенести эту папку на другой ПК. Не запускайте EXE прямо из окна архива.
2. Дважды нажмите **EngeeAgent.exe**. Через несколько секунд откроется браузер с приложением. Адрес по умолчанию: http://127.0.0.1:3081/.
3. Если 3081 уже занят, запускатель выберет свободный порт 3082–3090 и откроет правильный адрес. Повторный запуск откроет уже работающий экземпляр из этой же папки.
4. Откройте **Параметры**. В **Файлы проекта → Рабочая папка** подключите папку Engee, рядом в **Навыки** доступны навыки. **Engee** содержит **Аккаунт**, **Среда выполнения** и **Токены и конфигурация**; **Нейросети и подключения** содержит **Текущее подключение**, **Ваши подключения** (мастер и бесплатный API), **Локальные модели** и **Другие сервисы**. Маленькая Qwen уже лежит в `resources/LLM` и запускается встроенным сервером.
5. Для остановки нажмите кнопку питания **⏻** (подсказка «Остановить приложение») и дождитесь **Сохранение…**: сервер закрывается только после записи данных. При ошибке доступны **Повторить** и **Отмена**. Отмена во время записи ждёт её завершения и отменяет выключение. Закрытие вкладки браузера само по себе сервер не останавливает.

Пакет рассчитан на **Windows 10/11 x64**. Node.js и CPU-движок llama.cpp входят в ZIP: устанавливать Python, Node.js, Ollama и отдельную среду разработки не нужно. Упакованный Windows-запускатель использует системный .NET Framework, входящий в современные Windows. Для маленькой модели рекомендуется минимум 4 ГБ оперативной памяти; скорость зависит от процессора. Для интерфейса нужен современный браузер. Интернет нужен для облачных моделей и доступа к Engee.

На Linux/macOS можно использовать `sh start-engee-agent.sh`, но нужно самостоятельно предоставить нативный Node.js 22+ и, для локальных моделей, нативный llama-server. В этом архиве находятся только Windows x64 бинарные файлы; универсальная сборка для всех ОС не заявляется.

## Ярлык на рабочем столе

В публичном ZIP есть **«Создать ярлык на рабочем столе.cmd»**. После полной распаковки дважды нажмите этот файл: он создаст ярлык **Engee Agent** с логотипом приложения и путями к текущей папке. Логотип встроен в EXE. Если позднее перенесёте папку приложения, запустите создание ярлыка ещё раз, чтобы обновить его пути.

## Что находится внутри

| Путь | Назначение |
| --- | --- |
| `EngeeAgent.exe` | Запуск сервера и открытие браузера. |
| `Start-EngeeAgent.cmd` | Запуск в видимом окне для диагностики. |
| `resources/skills/` | Навыки для Engee. Новые навыки сохраняются здесь отдельными папками с `SKILL.md`. |
| `resources/web/` | Сервер, веб-интерфейс и каталог провайдеров. |
| `resources/runtime/` | Переносимые Node.js и llama.cpp с лицензиями и исходным кодом запускателя. |
| `resources/LLM/` | Встроенная GGUF-модель, сведения о моделях, лицензия и контрольная сумма. |
| `workspace/` | Начальная рабочая папка файлов Engee. Можно выбрать другую папку в настройках. |
| `data/` | Локальные настройки и журналы; создаются и изменяются во время работы. |

Все пути встроенных ресурсов вычисляются относительно распакованной папки. При переносе на другой компьютер укажите там свою рабочую папку Engee и свои параметры подключения. Встроенная папка моделей работает без настройки пути. Внешние абсолютные пути к папкам нужно выбрать заново, если таких папок на новом ПК нет.

## Локальная модель

Встроена **Qwen2.5-0.5B-Instruct, Q4_K_M**, официальный GGUF от Qwen, размер 491 400 032 байта. В разрешённых папках Engee прежних GGUF не было, поэтому эта компактная модель скачана отдельно из официального источника. Она предназначена для проверки подключения и простого чата. В проверке выражения `1+1/2*2` она ответила `3.0` вместо `2.0`: её арифметике и коду нельзя доверять без проверки. Для работы с Engee предпочтительнее сильная облачная модель или более крупная локальная модель.

Скопируйте дополнительные `.gguf` в `resources/LLM` либо выберите вручную другую папку моделей. Для работы нужны GGUF, поддерживаемые входящей версией llama.cpp; сырые `safetensors`, `pytorch_model.bin` и папки трансформеров автоматически не конвертируются. Для разделённого GGUF нужны все части рядом. Возможность загрузки ограничена памятью ПК и поддержкой архитектуры в llama.cpp.

Где искать модели и готовые локальные серверы:

- [Официальные модели Qwen](https://huggingface.co/Qwen), [встроенная модель](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF).
- [Каталог GGUF на Hugging Face](https://huggingface.co/models?library=gguf) — проверяйте издателя, лицензию и размер.
- [Ollama](https://ollama.com/library) — отдельный сервер; подключается как Ollama endpoint, его внутренние blobs не надо переносить в папку GGUF.
- [LM Studio](https://lmstudio.ai/) — отдельный локальный сервер с OpenAI-совместимым API.
- [llama.cpp](https://github.com/ggml-org/llama.cpp/releases) — движок и официальные сборки для разных платформ.

Дополнительные сведения: [resources/LLM/README.md](resources/LLM/README.md).

## Облачные и удалённые модели

Внизу **Диалога** рядом со скрепкой и папкой находится одна кнопка с именем текущей модели. Она открывает выбор сервиса и модели с группами **Локальные модели**, **Claude** и **Бесплатный API**. В последней расположен OpenRouter в режиме freeOnly: нужен **свой** API-ключ — его можно получить через **Параметры → Нейросети и подключения → Ваши подключения → Подключить бесплатный API → Войти в OpenRouter** без ручного копирования; модель должна быть `openrouter/free` или реально доступной `:free`. Лимиты аккаунта и доступность сервиса могут меняться; работа облака без регистрации и ключа не гарантируется. Локальная GGUF работает без облачного аккаунта. Другие сервисы добавляются через **Параметры → Нейросети и подключения → Ваши подключения → + Добавить подключение**.

В мастере выберите **API сервиса**, **Локальная модель** или **Программа**. Для API доступны Chat Completions, Responses, Anthropic, Gemini и собственный JSON с точным URL и путями ответа. Укажите адрес и модель из каталога сервиса; для собственного JSON модель необязательна, если её выбирает сервер. Для удалённого адреса нужен HTTPS, для сервера на этом компьютере допустим HTTP. У Chat Completions базовый адрес обычно заканчивается на `/v1`; для локального Ollama — `http://127.0.0.1:11434/v1`. Профиль меняется через **Изменить**, затем **Проверить** и **Использовать**; программа открывается в терминале только вашим нажатием.

Все шаги и ссылки находятся в [общей инструкции](resources/web/public/help/guide.html#connections), условия облаков — в [её разделе об облаках](resources/web/public/help/guide.html#cloud). `resources/LLM/FREE_CLOUD.md` оставлен как автономная справка архива. Встроенная локальная модель доступна без облачной регистрации и интернета.

## Работа с Engee и сохранение пакета

Основная работа выполняется в веб-интерфейсе: чат, вложения, команды, выбор модели, навыки, редактор файлов, создание файла, сохранение кода из ответа и запуск сохранённого `.jl`/`.ngscript` в Engee. Действия помощника с файлами и запуск кода подтверждаются по точному содержимому. Автосохранение перед выходом через ⏻ описано ниже. Проект постоянно подключён; отдельной галочки режима проекта нет. Claude Code автоматически продолжает текущую сессию приложения; `/clear` очищает только активный диалог и его контекст Claude; `/new` создаёт другой диалог, сохраняя прежний в локальной истории. Он получает явно добавленные в диалог материалы; исходные файлы меняются через подтверждённое сохранение в интерфейсе.

Значок **i** рядом с «Отправить» открывает необязательный просмотр получателя и подготовленного контекста. Сам просмотр ничего не отправляет. **Отправить** и Enter сразу отправляют запрос выбранной модели; отдельного подтверждения передачи нет. Подтверждения изменения файлов, сохранения и выполнения кода остаются.

Вложения добавляйте значком **скрепки** у поля сообщения. Соседний значок **папки** или `/files` открывает файловый браузер проекта: просмотр, редактор, сохранение, запуск в Engee и добавление в диалог. Рабочая папка и навыки находятся в **Параметры → Файлы проекта**. Значок **i** открывает окно **Контекст и команды** с двумя вкладками: **Контекст** — получатель и полный подготовленный запрос, просмотр ничего не отправляет; **Команды** — выбор заменяет текст поля выбранной командой, закрывает окно и возвращает курсор в поле, без выполнения. Допишите аргументы и нажмите **Отправить** или Enter. Ручной ввод `/` и автодополнение команд также доступны.

Для точного вычисления введите `/eval 1+1` или `/eval sin.(1:2)` в чате. Среду выполнения выбирает **⚙** рядом со значком **i**; по умолчанию используется Engee. После подтверждения выполняется именно показанный код, без обращения к LLM. Ручной код и фактический результат входят в следующий контекст нейросети; их можно увидеть в **i → Контекст**. Итоговую проверку проекта выполняйте в Engee. У блока `julia`/`jl` из ответа есть **Выполнить**: выбранная через **⚙** среда запускает точный код после подтверждения. Файловая кнопка **Выполнить в Engee** всегда использует Engee. Отказ от предложенного запуска Julia прекращает текущий запрос; остальные предложенные действия не выполняются. Среда сохраняется вместе с диалогом; `/clear` не меняет её. Команда `/status` показывает проверенные статус и версию среды. Ошибки выполнения кода показываются отдельно от ошибок входа. Подключение модели не гарантирует точность её ответов: в реальном тесте даже Qwen3.5-4B ответила `1` на `1+1`, поэтому расчёты проверяйте в Engee.

Локально сохраняются до **5 диалогов**. Значок **История диалогов** внизу рядом с **i** у поля сообщения открывает список; `/new` создаёт отдельный чат, `/clear` очищает только активный. При создании шестого окно **Создать новый диалог?** показывает имя самого давно открывавшегося неактивного диалога: **Создать диалог** удаляет его только после успешной записи нового, **Отмена** сохраняет все пять. Сообщения, черновик, вложения и среда выполнения относятся к своему диалогу.

При несохранённом файле предупреждение **Сохранить изменения файла?** предлагает **Сохранить**, **Не сохранять** или **Отмена**. Ошибка записи не закрывает редактор с правками. Кнопка **⏻** сначала сохраняет изменённый файл, параметры, историю и восстанавливаемые черновики. При ошибке приложение остаётся открытым; неполный новый файл, навык или подключение не создаётся автоматически из черновика.

В верхней вкладке **Терминал** выберите **Windows PowerShell** или установленный **Git Bash** и нажмите **Открыть терминал**. Это интерактивная оболочка в выбранной папке проекта: можно вручную запускать `claude`, `opencode` и другие установленные программы. При смене проекта нажмите **Новая сессия**, чтобы открыть оболочку уже в новой папке. **Закрыть сессию** завершает только этот терминал. Команды выполняются с обычными правами пользователя Windows; нейросеть сама терминалом не управляет. Ввод и вывод не записываются приложением в журнал. Для встроенного терминала нужна Windows 10 версии 1809 или новее. Выход через **⏻** завершает терминальные сессии после успешного сохранения данных приложения. После запуска оболочки и запущенные программы не возобновляются автоматически.

Если PowerShell блокирует запуск `opencode.ps1`, для версии OpenCode, установленной через npm, введите `opencode.cmd`. Для Claude Code с установленным исполняемым файлом используйте `claude`.

В **Параметрах → Engee → Токены и конфигурация** можно привязать токен Engee или API-ключ выбранного сервиса. JSON-редактор показывает маски `__KEEP_SECRET__`: оставленная маска сохраняет секрет, пустая строка удаляет его. Эти настройки не включаются в диалог модели.

В настройках виден сохранённый логин. Сохранённые пароли, токены и ключи обозначены точками и статусом «Сохранён». Для замены введите новое значение; «Показать/Скрыть» относится к этому новому вводу. Пустое неизменённое поле обычной формы сохраняет прежний секрет.

Приложение предназначено только для Engee. Укажите рабочую папку Engee и параметры Engee API в настройках. Доступ к закрытой сессии Engee требует ваших данных подключения; браузерная авторизация и ключи другого ПК автоматически не переносятся. Используйте существующие инструкции проекта и встроенную графику Engee.

Можно собрать два вида архива: публичный без личных ключей и личный для переноса ваших настроек Engee. Личный архив храните как конфиденциальный: он содержит личные параметры подключения. Данные доступа могут потребовать повторной авторизации. В публичном архиве получатель добавляет собственные ключи. Личный архив включает сохранённые подключения и их ключи; храните его конфиденциально и не распространяйте как публичный пакет.

Для пересборки откройте **Параметры → Компоненты → Собрать архив**. Общий ZIP исключает личные настройки; личный включает текущие настройки, данные входа и сохранённые подключения из `data/settings.json` и `data/connections.json`. После сборки скачайте файл по появившейся ссылке. Дополнительно оставлены `Build-Public-ZIP.cmd` и `Build-Personal-ZIP.cmd`. Рабочие файлы в архивы не включаются, кроме исходного проверочного примера; переносите выбранную рабочую папку отдельно. История, вложения, временные файлы, сессии Claude Code и терминальные процессы не входят в ZIP. История и вложения остаются в используемой папке приложения, рабочие файлы — в выбранной рабочей папке; сборка архива их не удаляет. Внешние программы и модели Ollama/LM Studio переносите либо устанавливайте отдельно. Проверьте на новом ПК пути к ним и выполните собственную авторизацию. Лицензии сторонних компонентов нужно оставить в пакете. Встроенный сборщик поддерживает ZIP до 4 ГБ; для более крупных наборов моделей используйте архиватор с ZIP64.

## Пути программ на другом Windows

Откройте **Параметры → Компоненты → Пути программ**. Здесь показаны фактически обнаруженные программы и встроенный GGUF runtime. Поля **Путь к Claude Code**, **Путь к PowerShell**, **Путь к Git Bash** принимают прямой путь; пустое значение включает автоматический поиск. **Сохранить пути** проверяет и сохраняет только эти три поля, **Проверить пути** обновляет обнаружение без установки или задачи модели. Поле Julia и его сохранение находятся в отдельной карточке. Изменения используются в следующих запросах или новых терминальных сессиях; уже открытая оболочка не переключается.

**Указать Codex, OpenCode или другую программу** открывает мастер типа **Программа** с исполняемым файлом и аргументами. Такой профиль открывается в отдельном терминале по вашему нажатию; он не заменяет встроенный Claude Code в диалоге. Для встроенного Claude задайте **Путь к Claude Code** и выполните собственный вход. Бесплатный аккаунт claude.ai сам по себе не включает Claude Code.

Внешние пути из личного архива могут отсутствовать на другом компьютере. Приложение попробует автоматический поиск и сообщит о найденной замене; если её нет, установите программу или укажите существующий путь. Ollama и LM Studio для чата настраиваются через API URL и фактическую модель, а не путь к EXE. Полные шаги: [Пути программ](resources/web/public/help/guide.html#program-paths).

## Julia для локальной проверки (необязательно)

В **Параметры → Компоненты** скачайте официальный Windows-установщик Julia и установите её вручную. Можно использовать PATH либо указать прямой путь к `julia.exe` и нажать **Сохранить путь**, затем **Найти Julia**. Для ручного REPL выберите **Julia — локальный REPL** во вкладке **Терминал**.

Для запуска из чата выберите **⚙ → Локальная Julia**, введите `/eval 1+1` или нажмите **Выполнить** у блока `julia`/`jl`, проверьте код, папку и программу, затем разрешите действие. Это отдельный процесс с обычными правами пользователя, без файловой песочницы: код может читать и изменять доступные файлы. Лимит — 30 секунд, код до 64 КиБ, вывод до 256 КиБ. Пакеты автоматически не устанавливаются. **Остановить** завершает только текущий процесс вычисления, не закрывая ручной терминал.

Локальная Julia проверяет чистый Julia-код; она не воспроизводит среду моделирования Engee. Итоговую проверку API Engee, `.ngscript` и `.engee` выполняйте в Engee. Шаги, загрузка и ограничения: [раздел Julia](resources/web/public/help/guide.html#julia), [выполнение кода](resources/web/public/help/guide.html#eval), [данные и права](resources/web/public/help/guide.html#privacy).

## Если запуск не удался

Запустите `Start-EngeeAgent.cmd`: окно покажет причину. Если порт занят, EXE автоматически попробует следующий; для явного выбора запустите `EngeeAgent.exe --port=3091`. При диагностическом запуске можно установить `ENGEE_AGENT_PORT` перед CMD. Сведения о запускателе сохраняются в `data/launcher.log`.

Если Windows сообщает об отсутствующем файле, распакуйте ZIP полностью, включая DLL в `resources/runtime/llama`. Не перемещайте один EXE отдельно от папки `resources`. Бинарные файлы скачаны из официальных источников; их версии и SHA256 записаны в `THIRD_PARTY.md` и `resources/runtime/SOURCES.json`.

## Границы проверки переносимости

Проверка распакованной копии в отдельном профиле на текущем Windows проверяет самостоятельный запуск комплекта, в том числе без внешних Node.js и Python в PATH. Это не проверка чистой Windows в отдельной виртуальной машине; проверка чистой ОС не заявляется. Облачные аккаунты, квоты и доступы получатель настраивает свои.
